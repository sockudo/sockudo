# Independent C2 review

Reviewed the core storage envelope and memory append-run snapshot, plus PostgreSQL, MySQL, DynamoDB, ScyllaDB and SurrealDB durable encoding, import, read and retention paths. This is a source and focused live-regression review, not a substitute for the parent workspace verification.

- DynamoDB snapshot keys overlapped ordinary version entry keys: `__text__#...` could be a valid raw-import message/version pair. Parent changed the snapshot namespace to a hexadecimal key containing no `#` and added a regression.
- DynamoDB raw import advanced append count only when advancing latest version, so older Append imports were not counted; its raw-import conditional error matching also still relied on generic error text. Parent owns the transactional correction and regression.
- SurrealDB raw import advanced the latest pointer without updating the newly cached full payload or append count. Subsequent reads/mutations could see stale content. Parent owns the transactional correction and regression.
- ScyllaDB raw imports into an existing atomic message wrote only legacy projections, which authoritative readers ignored. The scoped fix writes canonical version/delivery rows, latest state, append count, stream floor and open count in a same-partition conditional batch, then repairs legacy projections. Mutation CAS additionally fences append count so an older import cannot race through an unchanged latest version. Existing raw-import first-version-wins semantics are preserved; conflicting delivery identity rejects. Legacy-only chains retain their original projection path until their full retained chain is migrated.
- MySQL latest-pointer assignment order affected later conditional assignments. Parent identified and fixes this while reviewing the import paths.

Scylla's focused live regression covers older/newer imports into a compact atomic message, duplicate count stability, first-version-wins payload, full public latest and historical reconstruction, append limit, and next mutation serial. Raw output is `results/fanout/C2-scylla-import-live.txt`.

The core representation maintains an immutable prefix length per revision, reuses a growing snapshot only after exact predecessor prefix/fragment verification, and retains independent snapshots for divergent runs/imports. Public materialization checks durable UTF-8 prefix boundaries and fails if required snapshot data is missing. SQL snapshot decoding uses the caller transaction connection where applicable, avoiding pool-size-one self-deadlock. Snapshot retention must continue to outlive every historical reference and operation receipt; the parent owns the final purge/restart matrix and feature-gate migration documentation.

Final compact/GC cross-review (2026-09-05): no additional concrete correctness issue found after the import fixes. Checked that request idempotency reaches the produced envelope before receipt-retention planning, receipt pinning survives subsequent appended revisions, independent imported/divergent chains cannot overwrite another snapshot run, and snapshot writes share the authoritative mutation CAS/transaction. SQL snapshot refresh uses wall-clock age; Surreal excludes receipt pins and rechecks age/references during deletion; DynamoDB retries unprocessed snapshot keys and fails closed. Scylla snapshot lifetime matches its existing non-expiring atomic records. Parent owns the final restart/purge/fault matrix. Retained accumulated text is linear per append run; the implementation still rewrites growing snapshots and latest envelopes, so cumulative write/network bytes remain quadratic and must not be reported as a write-volume improvement.
