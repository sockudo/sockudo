**References:** [crates/sockudo-push/src/memory.rs:126-148](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-push/src/memory.rs:126) and 251-276 clone entire app/channel match before pagination; helper 1065-1089 then filters, sorts and clones returned rows again. [crates/sockudo-push/src/nosql/devices.rs:95-110](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-push/src/nosql/devices.rs:95) uses this default for list_devices. [crates/sockudo-push/src/nosql/subscriptions.rs:132-147](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-push/src/nosql/subscriptions.rs:132) and [crates/sockudo-push/src/nosql/publishing.rs:370-390](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-push/src/nosql/publishing.rs:370) similarly load/sort all app subscriptions or publish logs before taking a page.

For N rows and P page size, walking all pages copies/loads O(N^2/P) rows. Memory holds one global PushStore read lock while cloning (all apps share this store), delaying device/status writes. Surreal issues full remote SELECT and materializes rows for each apparent limited page. Document publish-log repair processes only a bounded result count but can read all lifetime events to produce it. This is distinct from P1: even a single complete registry traversal is superlinear.

**Improvement:** BTreeMap::range by app/channel/cursor and take P+1 before cloning where key ordering matches the existing cursor; preserve explicit cursor-string order for compound subscription keys. Override Surreal scan_app_page_by_pk with backend WHERE pk > cursor ORDER BY pk LIMIT. Add bounded indexed traversal for administrative subscription/publish-log lists. **Benefit:** estimated O(P) result construction per keyset page, O(N) total traversal, much smaller lock hold and RSS. Medium effort/low-medium risk. Tests must preserve opaque cursor/app validation and adversarial prefix ordering (`a` versus `a0`); do not simply remove the sort from incompatible compound key paths. Verify exactly P, P+1, >1MB Dynamo result sets, concurrent inserts and empty final page.

**Validation:** extend existing push fanout benchmarks with all-device page walks at 1k/10k/100k, page 100/1k; counting backend should assert returned-row construction bounded by P+1. Persistent database EXPLAIN/RSS/rows-read measurements not executed.

**Validation:** serialize full server PushQueueEnvelopeWire at 1/32/500 recipients and payload 256B/2KiB/provider limit, measure bytes/allocations and broker limits. For N connections, S attached channels and R app revocations, idle traffic includes >=2N owner GET/s, plus approximately 2N*(S+identity-target-count) GET/s and 2N*ceil(R/512) scan calls/s for revocable tokens. Even empty revocation state requires a scan. Redis scan-prefix may entail much greater shared-cache work; parent services audit covers implementation. The receive loop awaits sequential backend calls, so dependency slowness directly delays commands while the timer runs. Session timer tasks also add memory/wakeups, but this finding is about concrete replicated work.

**Improvement:** shared bounded per-app revocation snapshots driven by version/generation or one polling worker, with freshness/failure state and exact current <=500ms revocation behavior; batch ownership checks/fencing when possible and retain immediate local session commands. Authentication must still fail closed and not accept a stale snapshot after network error. More efficient batching alone is safe only if timing/fencing tests prove parity. Medium-high effort/high auth risk. **Benefit:** estimated app revocation reads O(apps*R) rather than O(N*R), owner calls reduced with batching; no percentage claimed.

**Validation:** shared-cache counting wrapper, 1/1k/10k idle connections, 0/10 channels, 0/512/10k revocations; track request/s, scan rows, receiver latency and p99 revocation disconnect. Exercise cross-node token revocation, delayed applies_at, issuedBefore, AUTH generation change, owner supersession, cache timeout fail-closed. Live cache/load not executed.

## A2. An empty stats queue imposes the full flush interval before critical acknowledgements [P2 latency, C]

**References:** [crates/sockudo-ably-compat/src/stats.rs:751-768](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-ably-compat/src/stats.rs:751) record waits a oneshot; run_stats_worker 957-965 sleeps flush_interval when the first Observe finds no more queued work; 1008-1032 merges then acknowledges. Current `stats_recording` benchmark measures batching throughput but not isolated ACK latency; add that distribution and persistent cache delay.

## A3. Stats query limits apply after reading/rolling up all retained minute buckets; memory retention is absent [P2, C]

Benefit estimated small-page query I/O proportional to requested interval, finite memory instead of process lifetime; medium effort/medium cursor/rollup risk. ## A4. Large projected/delta Ably fanout retains per-subscriber payload copies in recovery buffers [P2, C]

**References:** [crates/sockudo-ably-compat/src/runtime.rs:3193-3274](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-ably-compat/src/runtime.rs:3193) attach-gated subscribers clone whole message into per-subscriber gate; delta group loop 3405-3435 pushes projected.clone for each receiver; nonshared recovery 3490-3507 same; 3540-3562 appends to individual recovery gates. Ordinary same-channel plain delivery already uses a shared recovery tail. Encoded data is Arc-shared correctly; this finding is specifically retained protocol message clones for delta/projected/filter subscribers and simultaneous attaches.

For N such subscribers and retained K messages of payload B, recovery state can approach O(N*K*B) even when encoded projection/base is shared. Per-gate caps bound individual state, not aggregate per-channel memory; attach-gate clones occur while channel mutex is held. **Improvement:** store Arc<AblyProtocolMessage> or immutable projection reference per equivalent group in gates and clone only when applying consumer-specific mutations. Preserve subscriber base IDs, filtered projection, requested channel, serial and reset semantics. Benefit estimated lower payload memory and attach lock work, not lower unavoidable O(N) queue bookkeeping. Medium effort/medium-high recovery risk. Existing ably_vcdiff and compatibility_hot_paths benches can add 1/100/1000 delta subscribers, 256B/4KiB/64KiB payload, 0/10/100% attach-gated and disconnected recoverable subscribers, tracking allocations/RSS and continuity. Not measured; verify actual deep-copy field mix before an implementation.
