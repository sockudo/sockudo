### Transport coverage

All horizontal adapters alias or delegate to `HorizontalAdapterBase<T>` and share local fanout. Ordinary horizontal publish serializes the inner Pusher message, sends locally, then publishes a JSON `BroadcastMessage` containing the inner JSON string; receiving nodes deserialize outer+inner before local filtering. Thus broker traffic and parsing scale with all cluster nodes, even nodes without local channel subscribers. This is architectural context, not a proposal to weaken existing cluster semantics.

| Transport | Inspected behavior | Finding / caveat |
|---|---|---|
| Local | Shared JSON Bytes ordinary fanout; append-mode partition; bounded socket queue; compression grouping; predicate pass; rewind gates | F1, F4, F7; semaphore/chunk futures around synchronous `try_send` are a secondary CPU hypothesis. |
| Redis + Sentinel | Reused client handles, publish retry, global topics plus node/inbox routing, listener parsing and tasks | F2 unbounded per-message dispatch; bounded retries do not bound already spawned handlers. |
| Redis Cluster | Classic/sharded Pub/Sub, topology and shard listener reconnect, bounded 10k fan-in, internal push channel | F2 includes unbounded internal push channel and unbounded dispatch after fan-in; retry/backoff exists. |
| NATS | Client/subscription capacities, no-echo, response inboxes, system node discovery, chunked presence sync | F2 task dispatch bypasses capacities. No blanket recommendation to replace transport or add flush per message. |
| Kafka | Topic provisioning, stable producer, consumers and groups, publishing key, health, shutdown | F5 fixed key and one partition; blocking health metadata query. |
| RabbitMQ | Fanout exchanges, exclusive auto-delete queues, per-kind consumers and acks, publish/confirmation | F2 sequential handler plus no explicit basic_qos/prefetch or queue byte cap in transport. Actual broker policy/default must be recorded before asserting a memory-growth measurement. |
| Pulsar | Producer mutex, send_non_blocking and receipt, consumers/acks/subscriptions, shutdown | Receipt await correctly occurs outside producer mutex. Sequential per-kind consumer creates cross-channel head-of-line sensitivity; not independently measured. |
| Google Pub/Sub | Topic/subscription/publisher creation/reuse, sequential subscriber streams/acks, request/response routing | Sequential per-kind consumer head-of-line sensitivity; no independent service benchmark. |

## Ranked findings

### F1 — P1: compression-aware fanout repeats payload-sized preparation for every subscriber

**Workload:** V2 delta enabled, especially conflation-configured high-fanout channels, 1–64 KiB snapshots, mixed delta/non-delta sockets.

**References:** [crates/sockudo-adapter/src/local_adapter/broadcast.rs:151](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:151) loops recipients; [:166-168](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:166) extracts the same conflation value in each iteration; [:202-203](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:202) hashes each cached base; [:690-699](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:690) obtains and hashes it again at send time; [:743-746](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:743) base64-encodes the shared delta per recipient; [:527](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:527) serializes non-delta recipients via `send_message`; [:840-845](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:840) clones the full payload and serializes every full fallback. [crates/sockudo-delta/src/conflation.rs:38-43](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-delta/src/conflation.rs:38) parses the whole JSON and allocates a split-path vector. [crates/sockudo-delta/src/compression.rs:363-371](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-delta/src/compression.rs:363) repeats conflation extraction in each store operation. Direct serialization is [crates/sockudo-core/src/websocket/reference.rs:175-180](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/websocket/reference.rs:175).

**Mechanism:** Existing grouping computes the actual diff once per base group and shares stored payload bytes, but surrounding work remains O(S×P) parsing/hashing/full encode plus O(S×D) base64 for S recipients, payload P, delta D. When a conflation path is configured and socket state remains present, at least two identical conflation parses occur per delta recipient (grouping+state update). Without a configured path, extraction does not parse the payload. No need to replace algorithms/allocators to remove this cost.

**Evidence:** [conflation diagnostic](/home/radud/Desktop/Code/Rust/sockudo/audits/performance-2026-09-05/diagnostics/src/bin/conflation.rs) includes the exact current `conflation.rs` method with only minimal manager config storage. `rustc -C opt-level=3`, Rust 1.98.1, Linux x86_64, Ryzen 9 7950X (16C/32T), no tracing subscriber/network, 9 samples × 20 component iterations. Repository release compilation ran concurrently; no CPU affinity/frequency isolation. Payload data object with symbol `BTC` and x-filled content. At 1,000 recipient visits: 1,062 total bytes repeated extraction median 220,976 ns (min 218,857, max 223,987), once-and-borrow median 600 ns; 16,422 bytes repeated median 1,403,600 ns (1,389,511–1,408,809), once 1,768 ns; 65,574 bytes repeated median 5,350,019 ns (5,342,967–5,367,550), once 5,723 ns. 1/100/1,000 visits and all sizes are in raw output. These are measured extraction component costs, **not full-server improvements**. Allocations/CPU/RSS/network/p99 not measured.

**Smallest improvement:** Hoist conflation extraction once per broadcast/append-mode/configuration and pass resolved key into state storage. Cache a content fingerprint alongside immutable cached base, with generation/identity verification intact. Pre-encode shared delta body once per codec/base group. For non-delta sockets in this branch, reuse the already serialized immutable message using a format-aware bounded send helper. Full/delta per-socket sequence fields may still need small envelopes; group only identical wire metadata.

**Estimated benefit:** Removes S-dependent parsing and base64 duplication; measured extraction savings are a ceiling for only this component. Remaining per-socket enqueue, counters, sequences and network writes necessarily remain O(S).

**Correctness:** Preserve per-socket base sequence, negotiation algorithm, full interval, resubscribe/first-message fallback, tags and V1 exclusion. Do not group by payload hash alone as an authorization or correctness proof. Preserve bounded queue accounting and binary wire format. Test filtered divergent bases, identical content at different sequence positions, simultaneous publish/unsubscribe, slow consumers, both algorithms, encrypted channels, mixed V1/V2 and AppendMode::Full/Delta. Run delta tests, adapter integration, reconstruction/conformance, whole workspace and clippy for any implementation.

### F2 — P1: distributed input can outrun the bounded local queues through unbounded dispatch

Shared handlers can await cache/app lookup and compression at [crates/sockudo-adapter/src/horizontal_adapter_base/core.rs:480-487](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/horizontal_adapter_base/core.rs:480) and [:549-588](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/horizontal_adapter_base/core.rs:549).

**Mechanism:** If arrival λ exceeds handler completion μ, spawned tasks/payloads accumulate about (λ−μ)×time until another limit intervenes. Downstream socket/fan-in limits do not limit detached pending tasks, and the Redis push bridge can accumulate before its bounded stage. Dependency failure increases handler residence time. Bounded subscriber/client settings are insufficient after the listener drains into unlimited tasks.

**Smallest improvement:** Bound ingress execution and queued bytes before task creation; use a fixed worker/shard dispatcher keyed by app/channel (and separate bounded control/response capacity), with explicit overload semantics and queue-depth/drop metrics. Manage lifecycle/cancellation. For Redis synchronous push callback, use nonblocking bounded admission and an observable continuity-reset/overload policy; cannot await there.

**Benefit:** Code-backed bounded memory and more predictable tail latency; no production percentage measured. Throughput can decrease when backpressure activates; that is preferable to retaining unlimited work, but accepted-delivery/reset policy must be explicit.

**Correctness:** Keep per-channel ordering, control responses, presence first/last transitions, and recovery fail-closed. Do not silently drop stateful mutations. Test a blocking cache/handler, fast ingress, cancellation, queue saturation and recovery, every affected broker. Existing integration tests cover broker failure/races but no executed sustained overload result here.

**Related transport gap:** RabbitMQ adapter creates consumers without `basic_qos`; queues use empty argument tables ([crates/sockudo-adapter/src/transports/rabbitmq_transport.rs:366-382](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/transports/rabbitmq_transport.rs:366)) and acknowledgements occur only after sequential handler completion ([:416-425](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/transports/rabbitmq_transport.rs:416)). Broker default prefetch/policies decide actual memory placement. Add explicit bounded prefetch and measure with slow handlers; do not assume that sequential `.await` bounds broker/client buffers.

**Mechanism:** All coordinated channels on one node share a single serialized network lane; normal operation one RTT, first increment two, reset three (four if interval=1 and the first-increment branch applies). **Benefit / risk:** Estimated fewer round trips and unrelated-channel independence. No real RTTs measured. Changes to interval atomicity need multi-publisher tests, TTL expiry, reconnect/retry and counter overflow coverage; maintain full-message fallback on coordination failure.

### F4 — P2: selective tag/event predicates still visit every subscriber and often every subscription

**References:** Ordinary local publish takes all candidates at [crates/sockudo-adapter/src/local_adapter/connection_manager.rs:260-277](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/connection_manager.rs:260); filter helper at [crates/sockudo-adapter/src/local_adapter/broadcast.rs:937-945](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/local_adapter/broadcast.rs:937) delegates directly to [crates/sockudo-adapter/src/v2_broadcast.rs:201-231](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/v2_broadcast.rs:201). `matching_subscription_requires_document` ([crates/sockudo-adapter/src/v2_broadcast.rs:154-170](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/v2_broadcast.rs:154)) scans each socket's subscription map when no exact expression is found; failed exact predicates then scan wildcard subscriptions ([:105-138](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/v2_broadcast.rs:105)). Predicate matches use cheap checks in [crates/sockudo-filter/src/predicate.rs:382-414](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-filter/src/predicate.rs:382).

**Mechanism:** Even one match among 10k EQ subscriptions costs O(S); document preflight can add O(S×K) visits for K subscriptions per socket. Repeated identical compiled predicates are evaluated per subscriber, despite stable predicate identity. The old `FilterIndex` is currently **not populated or consulted by the server** (only definition/unit-test add/lookup calls), so its advertised O(1) lookup is not production evidence.

**Smallest improvement:** Skip expression preflight when no candidate subscription has an expression (maintain aggregate flags), then add an app/channel scoped candidate index for simple EQ/IN/events or group truly equivalent predicates and evaluate once. Retain the full predicate as final check; union exact and wildcard candidate views with annotation gating. Do not simply enable the legacy hash index: app scope and lifecycle consistency need review.

**Benefit:** Code-backed potential to scale with matching candidates/distinct predicates, especially sparse routing; unmeasured overall gain and meaningful maintenance cost. Retaining current scans can be better for small or mostly-match channels. Test wildcard+exact OR semantics, event+tags+expression AND semantics, mutation/recovery filters, annotation permissions, subscription updates and multi-app same channel names.

### F6 — P2: one slow AI deferred delivery batch stalls future timer polling globally

**References:** [crates/sockudo-adapter/src/handler/ai_rollup.rs:149-154](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/handler/ai_rollup.rs:149) awaits full batch processing before polling another tick; [:204-208](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/handler/ai_rollup.rs:204) joins all groups with only 16 concurrently active; [:274-276](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/handler/ai_rollup.rs:274) waits channel publish permit; [:303-341](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-adapter/src/handler/ai_rollup.rs:303) awaits egress and makes up to three total immediate attempts (two retries). `MAX_DUE_PER_TICK=4096`, bounded retries=4096 are already present.

**Mechanism:** A delayed app lookup, channel permit, or broker send can keep the worker inside a batch while other channels' newly due entries remain in heaps. `MissedTickBehavior::Skip` avoids a catch-up storm but cannot guarantee requested 20/40/100/500ms rollup windows under this wait. Existing rollup engine benchmarks do not exercise this worker with injected dependency delays.

**Smallest improvement:** Keep scheduling/tokens and delivery in one bounded event loop that polls deadlines while owned delivery futures progress, or fixed channel-sharded bounded workers. Preserve due-token claiming under the ordering gate; cap active tasks and bytes. Separate control/failure paths and expose due backlog / actual deadline lateness.

**Benefit / risk:** Estimated isolation of healthy channels from slow groups, not higher measured throughput. More concurrency uses bounded extra memory and can increase downstream load. Never coalesce originals in persistence/history/webhooks/push; this remains egress only. Test one intentionally stalled channel, 17+ channels, all-due and terminal storms, failures/retries, shutdown and serial continuity.

### F8 — P2: direct binary serialization clones entire protocol messages

**References:** [crates/sockudo-protocol/src/wire.rs:39-54](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-protocol/src/wire.rs:39), MessagePack [:44](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-protocol/src/wire.rs:44), Protobuf [:47](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-protocol/src/wire.rs:47); versioned equivalent [:86-96](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-protocol/src/wire.rs:86). Caller [crates/sockudo-core/src/websocket/reference.rs:175-180](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/websocket/reference.rs:175); history/replay and direct controls use send_message.

**Mechanism:** Conversion structs consume a `message.clone()` before encoding. Owned String/Binary data incur O(P) copies; JSON values may share their DOM backing, so not every message clone duplicates its entire payload. Conversion still traverses JSON values and allocates the encoded output. The current binary encoding views own their fields. This affects direct protobuf/msgpack sends; do not claim ordinary broadcast does this (see rejected hypothesis below).

**Smallest improvement:** Borrowing MessagePack encode view; reference-based Protobuf encoding/conversion that reuses immutable values where possible. Keep existing wire format and field order; avoid a blanket object-model redesign. Profile representative 1/16/64KiB JSON/string/binary payloads before adding complexity.

**Benefit / risk:** Code-backed avoidable copy component, no measured end-to-end improvement. Tests must cover binary data, large integer JSON preservation, every optional field, exact decoder/trailing bytes contract, V1/V2 gating and versioned frames.

## Independent challenge of root state-store findings

All three candidate findings are independently supported by source. These cross-checks add qualifications to avoid overstating their scaling or suggesting unsafe fixes; root owns their final ranking and diagnostics.

- **Memory history global write lock and linear seek:** [crates/sockudo-core/src/history/memory.rs:175](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/history/memory.rs:175) takes the shared map write lock for `read_page`; retention, cursor validation, predicate scan, and returned payload cloning happen under that guard through [:277](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/history/memory.rs:277). Both directions filter from the deque endpoint before `take(limit+1)` ([:247-260](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/history/memory.rs:247)). Deep cursor/bounds reads can scan O(H) retained entries and repeated pagination can cumulatively revisit most prefixes. A first unbounded page often stops after O(limit) entries, so do not describe every read as a full scan. Retention eviction is generally amortized; expiry bursts can be large. Shard locks by app/channel before changing data structures. A simple read-lock substitution omits retention mutation; binary search requires establishing serial/time ordering despite separate reservation and append arrival.
- **Memory version chain rescans:** Global writer acquired at [crates/sockudo-core/src/version_store/memory.rs:111](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/version_store/memory.rs:111) and [:231](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/version_store/memory.rs:231); `append_version` validates old chain plus incoming record at [:127-132](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/version_store/memory.rs:127), compare-and-apply at [:329-334](/home/radud/Desktop/Code/Rust/sockudo/crates/sockudo-core/src/version_store/memory.rs:329).
