# Independent challenge of root storage and HTTP candidates

2026-09-05, read-only. All three candidates survive cross-review, with the qualifications below.

1. **Per-append durable history retention work.** PostgreSQL history/postgres/writers.rs:243-262 unconditionally executes channel-scoped COUNT/SUM/MIN/MAX after each individual queued write. MySQL history/mysql/writes.rs:185-192 unconditionally invokes history/mysql/mod.rs:189-205 with the equivalent aggregate. Separate full COUNT is conditional on max_messages; full serial+size enumeration is conditional on max_bytes. It is the retained channel range, not necessarily the entire database table, and existing indexes may reduce random I/O but cannot avoid reading aggregate input. Append initially enqueues via try_send (Postgres history_store_impl.rs:55-93), with writers.rs:34-43 draining one record at a time, so the direct effect is writer service rate, durable lag and eventual queue-full/degraded behavior; do not imply every request waits for all this work synchronously.

   Dynamo history/dynamodb/writes.rs:81-88 unconditionally calls query_entries after put. queries.rs:35-67 loops all LastEvaluatedKey pages with no projection and decodes full payload-bearing entries. Scylla retention uses only serial/timestamp/size keys (history/scylla/entries.rs:10-36), not full payload; Surreal uses analogous key selection. Repeated remove(0) is O(E*N) for E removals and N retained rows (potentially quadratic after retention reduction/idle expiry), while steady one-row eviction is O(N), not O(N^2) per operation. Their per-row deletes are sequential network awaits. Preserve transaction/conditional update, multi-node stream ownership, duplicate insertion accounting and fail-closed continuity when replacing aggregates with incremental state; reducing only Vec shifting does not cure the full read.

2. **Scylla history page work ignores page bounds until after full fetch.** history/scylla/store_impl.rs:166-173 calls load_history_items_for_stream with only app/channel/stream/direction. entries.rs:39-73 selects payload_bytes and drains the entire paged query into Vec. Client bounds/cursor and take(limit+1) appear only at store_impl.rs:174-212. Backend paging avoids single giant server response but does not bound total application memory/traffic. A narrow requested limit can still load all retained payloads. The candidate is valid. Preserve runtime-state and stale-cursor checks at 121-164. Push serial cursor/range and limit into clustering-key query; for time filters, consume bounded chunks until enough matches while respecting continuity and existing has_more semantics.

3. **HTTP middleware buffers body outside DefaultBodyLimit enforcement.** middleware.rs:71-82 raw Body.collect occurs before AuthValidator authentication, and body is rebuilt at :100. Router applies DefaultBodyLimit::max at bootstrap/router.rs:664 but this only configures extraction limits; raw http_body_util collection does not use that extension. No RequestBodyLimitLayer/Limited::new wrapper found in server/core production Rust. Parent verified local Axum docs independently. Candidate valid for known and chunked lengths. Enforce configured byte limit while collecting (or outer actual body-wrapping layer), reject 413 at limit, and do not trust Content-Length alone. Preserve exact original bytes for body_md5/HMAC. Bytes clone at :100 is reference-counted O(1), so it is not an unnecessary full-body-copy finding. Auth query parsing can reject some requests before collection; a syntactically valid auth query still reaches unrestricted collection before secret verification.

No production changes or new runtime claims. Source-based cross-check only.
